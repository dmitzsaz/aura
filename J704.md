# J704 / M5 boot preparation

Target: Mac17,2 / J704AP / T8142. This fork retains the Aurora main baseline
`553b566f69275ff4e46ee6542a7236fb80a333a2` and J704 boot support.

The public board source lives in the companion Linux repository at
`arch/arm64/boot/dts/apple/t8142-j704.dts`, with an identical copy in U-Boot.
Aura prepares that static description using the current boot's Apple DT.
Do not use a captured live DTB as a template for a later boot or another Mac.

## Current-boot producers

- CPU operating points come from the PMGR voltage tables. PCIe's twelve RMW
  tuning tables come from `/arm-io/apcie` and its `pci-bridge0`/`pci-bridge2`
  children. The format-1 completion marker is published only after validation.
- GPU firmware and UAT reservations come from current ADT regions/segments.
  OPPs and the power sample period are reconstructed from current metadata.
- Display reservations follow existing locked DART tables. Inspection does
  not enable streams, allocate roots, write MMIO or invalidate translations.
  Table pages are reserved before handing those devices to Linux. Internal
  DCP and DCPEXT1 use their own carveouts and live firmware mappings.
- PMP tunables and memory identity come from the current ADT. Its firmware
  resides in PMP SRAM. The Linux report driver retains ownership of power,
  firmware checks, request seeding and activation of the dormant PMP nodes.
- Existing radio producers fill addresses and calibration through the board's
  `wifi0` and `bluetooth0` aliases. MTP firmware memory is reserved dynamically.

These DT producers do not start GPU, PMP or display firmware.
The existing decompressor also clears the ARM64 payload's runtime/BSS tail.

## Manual HAL300 profile

Before assembling the Aura boot image, apply a private overlay to the static
GPU node (`/soc/gpu@582600000`) containing:

- `apple,hal300-derived`: 103 records of five u32 cells: object, byte offset,
  width, low value and high value. Descriptors must match
  `src/kboot_gpu_t8142_fields.h` exactly.
- `apple,hal300-source-pstates`: frequency-Hz/core-mV/SRAM-mV triples for all
  source states, including state zero.
- `apple,hal300-source-period`: the source sampling period in milliseconds.

Aura validates the profile against this machine's current OPPs and sample
period, then builds GPU reservations on a copy of the DT. Missing or invalid
inputs leave the GPU disabled. Repeated preparation replaces its arrays.
There is no captured HAL300 graph file or automatic profile acquisition here.
Manual per-machine input is intentional; owner values are not public defaults.

Keep the resulting prepared DT through U-Boot into Linux. A raw static DTB
loaded later loses all these fixups.

## Verification and installation boundary

The earlier Aura/U-Boot combination was exercised through native J704 boot.
This new complete DT/producer integration still requires a cold-boot acceptance
test. `tests/run-j704-platform.sh`, `tests/run-t8142-gpu.sh` and
`tests/run-dart-inherited.sh` exercise production C with ASan/UBSan. The full
AArch64 Aura image builds. Actual private ADT/profile checks reproduce all ten
GPU reservations from the working handoff; the PMP check preserves its SRAM
and ordered activation contract.

Raw ADTs, Apple firmware, calibration, private HAL300 overlays, boot-specific
DTBs and built owner boot objects are not distributed. Build/install recipes
remain local. These sources are not a generic installer, and do not establish
working J704 audio or camera support.
